# 触达事件和身份更正

event_id由曝光源生成，跨重传批次保持不变。source_key包含来源命名空间，因此不同渠道相同文本标识不当然代表同一人。person是已确认的分析主体，不是用相似行为猜测的身份。

撤销事件针对指定event_id，替换传输批次不撤销该业务含义。身份合并或撤回合并针对明确的一组来源标识关系，合并无效不代表参与者的曝光事件无效。撤销登记为墓碑：事件换批次重传不复活，撤销批次按内容幂等，同名批次内容不一致会被拒绝。身份更正写入审计日志，可回放每次合并与撤回合并。

可更正集市按版本发布。每次刷新用湖中当前有效事件（原始事件减去墓碑）和当前身份映射全量重算，写成新版本文件后在目录事务中原子切换：更正到达时即使只涉及部分日期，也不会发布半套新身份口径，消费者要么读旧的完整版本，要么读新的完整版本；存在未确认标识时刷新整体失败，旧版本继续服务。日、周及渠道组合查询都基于同一版本快照：周按ISO日历周，周一开始；事件day在来源规范化后已经是约定的同一业务日期，不进行时区猜测。渠道组合查询的人数表示所选渠道并集里的不同分析主体，而不是各渠道人数之和；周人数同理不是日人数之和。版本汇总同时给出曝光次数、整体去重人数、日人数直接相加的对照值和已撤销事件数，用于解释曝光次数与去重人数为何不同。

无效事件不贡献曝光次数或人数。所有人数都是精确去重，不用近似计数，撤销后的误差不能被掩盖。封存摘录与封存周报只重现当时口径，不随后续更正改变；当前集市给出纠正后的值，影响范围按日度和周度列出相对任一版本的曝光次数与人数变化。更正以增量批次到达（撤销清单、合并关系），不要求上游先把全部历史合成一张新表。
